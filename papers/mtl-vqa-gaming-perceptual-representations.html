Learning Perceptual Representations for Gaming NR-VQA with Multi-Task FR Signals

MTL-VQA：以多任務全參考監督訊號，學習可遷移的遊戲影片品質表徵。

2. Research problem and motivation

Reported by source：雲端遊戲用戶端通常沒有原始參考影片，因此推論需採 No-reference Video Quality Assessment（NR-VQA，無參考影片品質評估）。遊戲影片的快速運動、風格化材質、HUD（畫面介面疊圖）與壓縮失真，可能使自然影片模型難以遷移；人類主觀評分資料也有限。僅以單一 Full-reference（FR，全參考）品質指標預訓練，可能受到該代理指標偏差影響。（PDF 第 1–2 頁，§1–2）

Research question

作者探討：能否結合多種互補的 FR 監督訊號，學習可遷移的品質特徵，再以凍結特徵與輕量回歸器，改善跨資料集及少量人類標籤情境下的遊戲 NR-VQA？此為依作者動機整理的研究問題。（PDF §1、§3）

研究定位：本文主要模型為 ResNet-50 與品質回歸器，沒有文字輸入或語言分支；屬於本站影片品質評估與遷移研究範圍，不應稱為視覺語言模型或多模態語言模型。

3. Method overview and model architecture

Reported by source：Fig. 1 與 §3 描述兩階段流程：先用可取得參考影片的 PGC（Professionally Generated Content，專業產製內容）學習表徵，再凍結編碼器，對目標遊戲影片進行 NR 品質預測。

  1. 產生代理監督：以 ffmpeg 將原始參考影片壓縮為 0.25、0.5、1、2、5 Mbps，其他編碼參數固定；計算壓縮影片與參考影片間的 FR 分數。作者報告共有 885,000 個訓練影格。（§3.1）
  2. 共享編碼器：以 ImageNet 初始化的 ResNet-50 擷取影格特徵；預設三個任務分別以 MLP（Multilayer Perceptron，多層感知器）預測 VMAF、SSIM、MS-SSIM。（§3.4–3.5）
  3. 多任務最佳化：每個任務使用 Smooth-L1 loss，β = 1。先計算各任務對共享編碼器的梯度，再以 MGDA（Multiple Gradient Descent Algorithm）／MinNormSolver 尋找非負、總和為 1 的任務權重，藉加權聯合損失更新編碼器與任務 head。（§3.2）
  4. 下游品質預測：凍結編碼器，將影格特徵做 temporal mean pooling（時間平均池化），再由回歸器輸出影片品質。標準切分使用 RBF-kernel SVR（徑向基底核支援向量回歸）；few-shot 另評估 Ridge regression（嶺迴歸）。（§3.4、§4.1）

預設代理指標：SSIM 為結構相似度、MS-SSIM 為多尺度結構相似度、VMAF 為 Video Multimethod Assessment Fusion。作者根據訓練資料的 FR-to-MOS 對齊情形選擇三者，並以 FovVideoVDP 組合做消融；它們是預訓練目標，不是下游主要評估指標。（Table 1、§3.5、Table 3）

實作條件：原文報告預訓練每兩影格取一影格、縮放至 960 × 540，使用 SGD、batch size 20。評估每秒均勻取一影格；LIVE-Meta MCG 採資料集提供的顯示尺寸，其餘評估集縮放為 960 × 540。（§3.4、§4.1）

標籤使用範圍：FR 代理預訓練不直接使用人類品質標籤作為訓練目標，但預設代理組合的選擇參考了 FR-to-MOS 分析；標準切分及 few-shot 的下游回歸器仍需目標 MOS（Mean Opinion Score，平均主觀評分）。不能將整套流程稱為完全無人類標籤，也不能將 NR 推論等同 zero-shot。

4. Datasets and evaluation protocol

Datasets

Reported by source：下列名稱、用途與規模取自提供 PDF 的 §3.1、Fig. 2 及 Table 2；規模尚未逐一與原始 Dataset 官方版本核對。來源與評估語料分離，是作者的設計報告，不代表本專案已獨立稽核跨語料內容重複。

  • GamingVideoSET、KUGVD、CGVDS：PGC 代理預訓練來源。Fig. 2 分別標示 90、90、340 videos；此處不將這些圖中規模當作新增壓縮後的訓練影片總數，也不將 885,000 影格當成影片數。
  • LIVE-Meta MCG：PGC 評估集；Table 2 標示 600 videos。
  • LIVE-YouTube Gaming：UGC（User Generated Content，使用者產製內容）評估集；Table 2 標示 600 videos。
  • YouTube UGC-Gaming：YouTube UGC 的遊戲子集；Table 2 標示 108 videos，不是完整 YouTube UGC Dataset 的規模。

目前尚無上述 Dataset 的本站獨立條目，因此不建立空白或不存在的連結；資料集授權、主觀評分程序與版本仍須未來依各官方來源另行整理。

Three evaluation protocols

  • Zero-shot：§4.1 定義為 FR 預訓練編碼器凍結，以來源 PGC 的 MOS 訓練 MLP head，再直接套用目標資料集，不使用目標標籤。Table 4 的 K = 0 卻列為 SVR／Ridge 跨資料集遷移，與此段 head 描述有差異，須查明實際設定。
  • Few-shot：編碼器凍結，以目標資料集 K ∈ {10, 20, 50, 100} 個有標籤片段擬合 SVR 或 Ridge，在剩餘片段評估；作者報告 100 次隨機 K 抽樣的中位數。（§4.1、Table 4）
  • Standard split：每個評估集做 100 次獨立 content-disjoint（內容不重疊）80%／20% 訓練／測試切分；訓練部分再做依內容切分的五折交叉驗證，以 grid search 選擇 SVR 的 C、γ，再於完整訓練部分重訓。這項協定會使用目標資料集 MOS。（§4.1、Table 2）

Evaluation metrics

  • SRCC：Spearman Rank Correlation Coefficient，衡量預測與 MOS 的排序一致性；越高越好。
  • KRCC：Kendall Rank Correlation Coefficient，另一種排序一致性指標；越高越好。
  • PLCC：Pearson Linear Correlation Coefficient，衡量線性相關程度；越高越好。
  • RMSE：Root Mean Square Error，均方根誤差；越低越好，不能忽略 MOS 尺度而直接跨資料集比較。

原文 §4.1 指出 SRCC／KRCC 使用未映射預測，PLCC／RMSE 使用 logistic mapping 後的預測，重複切分結果報中位數。原文未充分交代 logistic mapping 的擬合資料與參數；解讀 PLCC 時須保留此不確定性。

Single-proxy vs. multi-proxy ablation

Table 3 的 SRCC：VMAF-only ST-VQA → 預設 MTL-VQA，在 LIVE-Meta MCG 為 0.8965 → 0.9434，LIVE-YouTube Gaming 為 0.8254 → 0.8486，YouTube UGC-Gaming 為 0.7377 → 0.8292。這是作者報告的消融比較，不是我們重現的結果。

預設組合並非每個資料集最佳：在 YouTube UGC-Gaming，VMAF + MS-SSIM + FovVideoVDP 達 SRCC 0.8680、PLCC 0.8980，優於預設組合；作者認為代理組合的最佳選擇具有資料集相依性。（§4.3、Table 3）

6. Authors’ stated limitations and future work

  • 極低品質片段的 HUD 可能主導池化特徵；作者提出 HUD-aware masking 作為未來方向。（§5）
  • 快速運動與閃爍需要更強的時間建模；作者另提出 codec／artifact-aware 輔助任務。（§5）
  • 沒有對所有資料集均最佳的代理組合；target-aware proxy selection，以及納入 LPIPS、DISTS 等指標，仍屬未來工作。（§4.3）
  • 大幅領域差異下，沒有目標監督的遷移仍具挑戰。（§4.2）

7. Our analysis and possible Research Gaps

Our observation / AI analysis：以下是依原文進行的分析與待驗證問題，並非作者原句或已完成實驗；未替本專案決定新的 benchmark 或研究方法。

  • 遷移與 zero-shot 必須分開：代理預訓練語料與目標語料不同，支持「表徵跨資料集遷移」的研究定位；但 Table 2 的回歸器使用目標 MOS，其高相關不能直接證明 target-label-free 表現。
  • Few-shot 的測試規模：依原文 108 支影片與「剩餘片段測試」規則推算，K = 100 時每次僅剩 8 支影片。PLCC 0.9301 應連同測試規模解讀，不能與不同測試集合的 Table 2 PLCC 直接比較。原文未提供此數值的信賴區間；評估更大、固定測試集是可討論的研究方向。
  • 提升並非逐點單調：Table 4 的 YouTube UGC-Gaming / Ridge 在 K = 10 時低於 K = 0；因此應描述整體較多標籤的改善趨勢，不能聲稱每增加標籤都改善。
  • 協定與版本需要對齊：§4.1 的 zero-shot MLP 與 Table 4 的 SVR／Ridge 描述需釐清；官方 README 的部分重現步驟使用 mean，而本 PDF 報 median，且提及本 PDF 沒有的 Table 5。應鎖定論文版本、checkpoint、聚合方式與實際資料子集，再設計重現。（官方重現說明；存取 2026-11-16）
  • 預訓練細節差異：PDF 報 batch size 20，官方 README 的訓練命令使用 320；兩者是否對應不同版本或設定尚未驗證，本文不自行修正原文數字。
  • 最佳化機制的獨立效果：Table 3 比較單任務與多任務／代理子集，但未單獨隔離等權重與 MGDA 的差異。不能將所有增益歸因於梯度平衡；此為可進一步驗證的機制問題。
  • 部署主張的證據：作者提出實用、低延遲雲端遊戲品質監測的方向，但提供 PDF 未報明確硬體、推論延遲、FPS 或成本測量；尚不能據此確認特定裝置上的即時效能。
  • 與 VLM 的可能連結：以語言輔助辨識失真、HUD 或時間事件，可作為未來假說；本文沒有執行相關 VLM 實驗，也沒有支持此方向有效的直接結果。
